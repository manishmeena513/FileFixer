## Executive Summary

A comprehensive, read-only architectural survey of all routes, page components, catalog structures, SEO configuration, and PWA assets was conducted across the FileFixer application.

Key findings include:
1. **The 33 Static Routes**: Exactly 33 static routes are generated during `next build` (confirmed via `.next/server/app-paths-manifest.json` and Turbopack compiler output). These consist of **26 user-facing page routes** and **7 system/metadata routes** (`/_not-found`, `/_global-error`, `/apple-icon.png`, `/favicon.ico`, `/icon.svg`, `/robots.txt`, `/sitemap.xml`).
2. **Metadata Architecture**: 16 client-rendered route folders use a dedicated `layout.tsx` Server Component to define page-level OpenGraph and SEO metadata. 7 routes are Server Components defining `metadata` directly in `page.tsx`. However, **3 client pages (`/image-studio`, `/pdf-studio`, `/privacy-cleaner`) currently lack a `layout.tsx`**, causing them to inherit generic root metadata without custom canonical URLs or titles.
3. **Tools Catalog Structure**: The central catalog in `src/lib/tools.ts` defines **20 distinct tools** categorized into 4 groups (`Images`, `PDF`, `Batch`, `Utilities`). A historical copy discrepancy was discovered on the Homepage where text refers to "all 13 tools" (originating from FileFixer 1.0/2.0 before the addition of Studios, Workflows, Privacy Cleaner, etc.).
4. **Local-First Privacy Parity**: All 20 utilities adhere strictly to client-side in-browser processing via HTML5 Canvas, `pdf-lib`, Web Workers, and browser File APIs. No server upload endpoints exist in `src/app/api` (the directory is empty).
5. **PWA & Offline Infrastructure**: Full service worker caching (`public/sw.js` with cache name `filefixer-v3`) precaches core routes, while `PwaRegistration.tsx` mounts on root `layout.tsx`. All icons (`icon.svg`, `icon-192.png`, `icon-512.png`, `apple-icon.png`, `apple-touch-icon.png`) and the voluntary support UPI QR code are stored in `public/`.
